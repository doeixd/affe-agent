# Review, third pass

Follows [review-2026-08-24.md](./review-2026-08-24.md) and
[review-2026-08-24-2.md](./review-2026-08-24-2.md). This pass covers the
coding toolkit's own tools — which neither earlier report reached — and the
export package that landed in `d4ed1c8` after the second one.

The headline finding is a denial of service reachable from model output, and it
is demonstrated rather than argued.

---

## 1. A model can hang the process with a search pattern — **demonstrated**

**Severity: high (availability, and it takes the whole process), scope: needs a
design decision, not a patch.**

Two parameters of the `search` tool reach a regular-expression engine unbounded
and unvalidated, both of them model-supplied.

**The regex itself.** `CodingToolkit.ts:599`:

```ts
const regex = yield* Effect.try({
  try: () => new RegExp(pattern),
  catch: () => `invalid regular expression: ${pattern}`
})
```

`pattern` is whatever the model wrote. The guard catches a *syntactically*
invalid regex and nothing else, so a classic catastrophic pattern —
`(a+)+$`, `(x+x+)+y` — is accepted and then run against every line of every
file in the workspace.

**The `include` glob.** `glob.ts` compiles `{a,b}` into `(?:a|b)`, so nested
brace groups become nested alternations. Measured against the real module:

```
REDOS PROBE: { elapsed: 3084, result: false, patternLength: 121 }
```

**Three seconds for one filename**, from a 121-character pattern
(`"{a,a}".repeat(24) + "b"`). And `Glob.matches` is called *inside the file
loop* (`CodingToolkit.ts:610`), recompiling and re-running per file — so a
thousand-file workspace multiplies that by a thousand.

**Why this is worse than an ordinary slow tool.** Regex matching is synchronous.
It does not yield, so:

- `Effect.timeout` around the tool **does not help** — there is no suspension
  point at which to deliver the interruption.
- `AgentSession.interrupt` does not help, for the same reason.
- It blocks the *event loop*, so in a process serving several sessions — which
  is the whole point of `AgentSessionHost` and the planned `AgentServer` — one
  session's bad regex freezes all of them, plus the HTTP server.

The agent becomes unkillable by its own harness. That is a different category
from "a tool took a while".

**This is not a hypothetical model.** Models write greedy backtracking regexes
routinely and by accident; `(.*)+` shapes appear in ordinary "find all
functions" attempts. Malice is not required.

**Suggested fixes**, and none of them is one line:

1. **Bound the inputs.** Cap `pattern` and `include` length (say 200 and 100
   characters) and reject brace nesting past a small depth. Cheap, partial, and
   it turns "hangs forever" into "hangs briefly" — it does not fix `(a+)+$`,
   which is short.
2. **Compile the glob once**, outside the file loop. Pure win, no downside, and
   it removes the per-file multiplier from the glob half.
3. **Run matching where it can be killed.** Effect cannot interrupt synchronous
   code, so the only real answer is a boundary that can be: a worker.
   `effect/unstable/workers` is listed in
   [audit-effect-ecosystem.md](./audit-effect-ecosystem.md) Group 3 as *"a real
   isolation boundary for `/subagent` and `/sandbox`, if isolation ever needs to
   be more than a convention"*. This is the concrete reason it might.
4. **Use a linear-time engine** for the model-supplied pattern — RE2 has no
   backtracking and cannot exhibit this. A dependency, and the standard answer
   to exactly this problem.

**Recommend 1 and 2 now** — they are hours, not days, and they remove the
amplification and the trivially-long patterns. Then decide between 3 and 4
deliberately, because "the harness cannot interrupt its own tool" is a property
worth choosing rather than inheriting.

**Missing tests.** There are none for either parameter's pathological case. Add
one per input asserting a bound is enforced — and note that a test asserting
*elapsed time* will be flaky, so assert the **refusal**, not the duration.

## 2. `/export` ships without the notice its own plan requires

**Severity: medium (a foot-gun at exactly the wrong moment), scope: a paragraph.**

`d4ed1c8` publishes `affe-agent/export`. Redaction is milestone E3, so
its absence is deliberate sequencing rather than an oversight — but
`plan-snapshot-export.md` §3 asks for something E1 did not deliver:

> the default is documented as *no redaction* so the choice is visible rather
> than assumed

The shipped module documents no such thing. `Export.ts` and `export/index.ts`
contain **zero** occurrences of `secret`, `sensitive`, `redact` or `content`.

What makes this sharp is that the module's own opening sentence is the risk
statement:

> A transcript that leaves the process.

It is one sentence away from saying *what* leaves with it — tool results, which
is to say file contents, command output and environment. A transcript pasted
into a bug report is a transcript published, and the plan says so in §3.

**Suggested fix.** Three lines in the module doc: an export carries tool results
verbatim, nothing is redacted, and E3 is where that changes. That restores the
property the plan asked for — the choice being *visible* — without waiting for
the feature.

## 3. The glob regex is recompiled once per file

**Severity: low (performance), scope: three lines.**

`Glob.matches(pattern, path)` calls `new RegExp(...)` on every invocation, and
the caller invokes it per file. For a large workspace that is thousands of
identical compilations, and it is also the multiplier that turns finding 1 from
slow into unusable.

**Suggested fix.** Return a compiled matcher: `Glob.matcher(pattern)` yielding a
`(path: string) => boolean`, built once before the loop. `matches` can stay as a
one-shot wrapper for the tests that use it.

## 4. `walk` is unbounded, and its spread has a hard ceiling

**Severity: low-medium, scope: one line for the ceiling.**

```ts
files.push(...(yield* walk(sandbox, entry.path, skip)))
```

Two things:

- **`push(...arr)` passes the array as arguments**, and engines cap argument
  count — typically around 65k–125k. A directory subtree with more files than
  that throws `RangeError: Maximum call stack size exceeded`, which reaches the
  model as an opaque failure rather than "this tree is too large". Use
  `for (const f of child) files.push(f)` or `files = files.concat(child)`.
- **There is no depth or count bound.** `IGNORED_DIRECTORIES` skips `.git`,
  `node_modules`, `dist` and friends, which handles the common case, but a
  workspace with a genuinely deep or wide tree walks all of it into memory
  before a single line is searched.

**Checked and sound**, and worth recording because it is the obvious worry:
**symlink loops are not reachable.** `local.ts` lists with
`readdir(withFileTypes: true)` and branches on `dirent.isDirectory()`, which is
`false` for a symlink — so `walk` never recurses through one. A symlinked file
is listed and then read through the sandbox's `realpathSync` containment check,
which refuses a target outside the workspace. Both halves are right; neither is
tested, and the second is a security control.

## 5. Also checked, and sound

- **The export's version handling.** `decode` refuses an unknown version *by
  name* before reading the payload, which is the point of having a version at
  all — a decoder that fails later on a missing field tells you nothing useful.
- **`Export` embeds `Snapshot` unchanged**, so restoring from an export is
  restoring from a snapshot, and there is a test that does exactly that. The
  distinction the plan rests on survived implementation, which is not always
  what happens to a distinction.
- **The replacer chain, the web toolkit's permission projections and `Redacted`
  key handling, and the tree's activation semaphore** — covered in pass two,
  unchanged since.

---

## Suggested order

1. **Cap the two model-supplied patterns and hoist the glob compile**
   (findings 1.1, 1.2, 3). Hours, and it removes the amplification.
2. **Add the export's no-redaction notice** (finding 2). Minutes.
3. **Fix the `push` spread** (finding 4). One line.
4. **Decide about worker isolation or RE2** (finding 1.3/1.4) — the real fix,
   and the one worth choosing rather than defaulting into.
5. Add tests for the symlink containment path, which is a security control with
   no coverage.

## A pattern across the three passes

Each report has found the same shape once: a control that is correct in the code
and unproven by the tests. Pass one, the SSRF table denying less than the guard
does. Pass two, a conformance suite that could not see a race because its
backing never yields. Pass three, symlink containment with no test and two
regex inputs with no bound.

The code in this repository is consistently better than its test suite's
*coverage of adversarial input* — which is a good problem to have, because it is
cheaper to fix than the reverse.
